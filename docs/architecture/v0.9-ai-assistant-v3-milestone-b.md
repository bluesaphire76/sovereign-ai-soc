# Grounded Analytical Assistant V3: Milestone B

## Status and Boundary

Milestone B turns the typed Milestone A analytical package into a grounded,
discursive Assistant response. It adds no write action and no unrestricted
prose fact channel. The complete production path is:

```text
validated conversation state
  -> semantic intent and focus
  -> authoritative retrieval and typed evidence
  -> cross-incident candidate discovery and SQL rehydration
  -> V3 analytical context package
  -> dynamic GroundedAnswerPlanV3 schema
  -> exactly one provider generation
  -> deterministic plan validation
  -> compositional discourse renderer
  -> response blocks and exact source attribution
```

The generation produces a plan, not answer prose. All visible prose is
realized deterministically from typed plan units and the validated package.
There is no critic, citation repair, prose rewrite, same-model retry, model
switch, or second generation.

## GroundedAnswerPlanV3

The closed plan records answer intent, detail level, audience, ordering,
sections, typed analytical units, exact evidence references, limitations, and
next checks. Each unit also carries a proposition type, importance,
rhetorical role, evidence priority, and validated subject record IDs. Unit
types distinguish recorded facts, recorded correlation, analytical
derivation, semantic similarity, comparison, difference, pattern, reference
explanation, advisory guidance, absence, and non-implication.

The model-facing representation is a compact closed object: `sections` is
keyed by stable section codes, and each section maps to a bounded array of unit
objects containing `kind`, a closed discourse `mode`, importance, and exactly
one of `refs` or `code`. Duplicate sections are structurally impossible, while
semantic tuple slots prevent duplicate comparison and relationship units.
Intent, detail level, audience, ordering, and closed proposition semantics are
normalized deterministically into the typed plan.
The wire object is normalized exactly into the typed section list before
Pydantic validation; malformed JSON, unknown keys, ambiguous refs, and
incompatible fields are not repaired.

## Dynamic Schema

Each request receives a strict schema generated from its context package. Ref
enums contain only IDs available in the current model-facing evidence view.
The view is a deterministic projection of the larger validated package and is
bounded to four candidates, eight relationships, 32 operational atoms, four
reference atoms, and two advisory atoms. Relationship evidence and selected
incident facts are retained; the full package and registries remain available
to the validator and renderer.

Sections and unit types are restricted by intent and available context. Unit
variants expose only the compact `refs` or `code` field. Exact canonicalization
maps refs to the corresponding typed fact, relationship, candidate, reference,
or advisory field. Comparison refs contain one operational atom type across
multiple incidents. Pattern refs contain one analytical relationship type.
Authority-specific relationship enums keep recorded, derived, semantic, and
temporal evidence separate.

The schema exposes bounded adaptive section variants driven by intent and the
evidence actually available. Fact lookup stays narrow; open analytical intents
can select additional evidence, timeline, technical-context, relationship, or
caveat sections within their usefulness contract. Sections can contain one or
two compatible units, and a unit can group several semantically compatible
facts. Multi-reference comparison and pattern units use complete, prevalidated
ref arrays selected from a closed enum, so duplicate or partial sets cannot
reach the parser even when a provider does not enforce `uniqueItems`. Refs,
candidate mentions, and advisory checks have independent caps. The V3
structured completion budget defaults to 768 tokens and remains hard-bounded
by the 2,048-token gateway contract.

## Plan Validation

`GroundedAnswerPlanV3Validator` resolves every ref by exact registry lookup. It
checks intent, section/unit compatibility, scope, authority, relationship
class, comparison atom type, pattern membership, supported absence,
limitation relevance, and duplicate semantics. It also enforces bounded
non-implications:

- recorded correlation does not prove compromise;
- analytical derivation does not prove causality, common attacker, or campaign;
- semantic similarity is not recorded correlation;
- candidate ranking means comparison relevance, not risk or compromise.

A general analytical caveat may cover several derivation subtypes; otherwise
all subtype-specific caveats must be present. Candidate wording embeds its
closed ranking caveat directly. Invalid output fails closed to a deterministic
plan without JSON repair or provider retry.

## Rich Discourse Renderer

The renderer accepts only a validated plan plus a V3 package. Its deterministic
paragraph planner aggregates compatible facts, maintains unambiguous subject
continuity, contrasts comparison facts, synthesizes multiple relationship
signals, explains selected reference knowledge, transforms typed advisory
guidance, and places caveats after substantive findings unless a limitation is
the direct answer. It supports Italian and English and emits optional
backward-compatible blocks such as `direct_answer`, `key_findings`,
`related_incidents`, `evidence`, `technical_context`, `analysis`, `next_check`,
and `limitations`.

Source attribution is derived from unit refs. Relationship citations recurse
to their authoritative evidence atom refs. Duplicate normalized paragraphs are
suppressed, and no citation is inferred from rendered text.

## Cross-Incident Answers

Comparison and pattern answers use only explicit selected IDs, validated
conversation IDs, same-case links, deterministic candidate signals, and
semantic candidate IDs that survive SQL rehydration. The response explicitly
distinguishes:

- platform-recorded correlation (`OPERATIONAL_AUTHORITATIVE`);
- deterministic analytical relationship (`ANALYTICAL_DERIVATION`);
- semantic comparison candidate (`SEMANTIC_CANDIDATE`).

Candidate rank is investigation/comparison utility only. Same host, rule,
MITRE technique, case, correlation type, or temporal proximity does not create
causality, compromise, attacker identity, or campaign attribution. Conversation
state contains only validated IDs and refs; previous Assistant prose is never
authority.

## Incident Semantic Index

Cross-incident semantic discovery uses the dedicated
`incident_semantic_index` Qdrant collection rather than the advisory
`security_kb` namespace. Documents are built deterministically from bounded
authoritative fields and carry stable incident UUID, document/embedding
version, source fingerprint, and typed discovery payload.

The lifecycle supports status, full-estate rebuild, upsert, refresh, and delete
through:

```bash
./ai-soc incident-index status --json
./ai-soc incident-index rebuild --json
```

An uncapped rebuild and status check cover the complete eligible SQL corpus;
an optional explicit limit remains available for diagnostics. Embeddings are
batched, and reconciliation reports eligible/indexed records, missing IDs,
duplicates, stale fingerprints, and embedding failures. Incremental indexing
is best-effort and never blocks incident handling.
Request-path retrieval requires a prewarmed embedding runtime. Qdrant failure
degrades semantic discovery; every returned ID is rehydrated from SQL and its
fingerprint is checked before use. Qdrant text and score never become an
operational fact, correlation, risk, severity, or compromise state.

## Activation and Failure Handling

V2 remains the default rollout mode. V3 can be selected without changing a
sensitive environment file:

```bash
AI_ASSISTANT_RESPONSE_ARCHITECTURE=v3 \
AI_SOC_ASSISTANT_V3_MAX_OUTPUT_TOKENS=768 \
./your-existing-api-start-command
```

`AI_ASSISTANT_RESPONSE_ARCHITECTURE=v2` restores the V2 response path. Failures
are classified as context, schema, structured output, plan validation,
renderer, semantic-index, gateway, or deadline failures. All fail closed to a
deterministic grounded response; no stage invokes another model generation.

## Security and Observability

The contextual Incident/Case routes retain existing authentication and RBAC.
The current platform authorization model does not expose row-level incident
ACLs; candidate SQL rehydration therefore operates within the same global
role-authorized data boundary as authoritative incident retrieval. Adding
row-level ACLs later requires applying the same predicate before candidates
enter the package.

Metadata reports plan/section/unit counts, phase timings, prompt/completion
tokens, fallback reason, semantic-index status, provider generation count,
automatic retries, and model switches. Prometheus labels remain
low-cardinality and contain no record IDs, questions, evidence, or output.

The read-only quality matrix is reproducible with:

```bash
AI_INFERENCE_GATEWAY_SOCKET=/path/to/gateway.sock \
  .venv/bin/python scripts/validate_assistant_v3_milestone_b.py
```

It uses real records, a serial gateway workload, deterministic structural
metrics, and manual samples. A validation-only inter-query delay can be used to
keep local GPU thermals from contaminating per-response latency measurements.
It does not create incidents/cases or use a second LLM evaluator.

## Product Quality Closure

Milestone B.1 adds intent-specific usefulness contracts, declarative evidence
priority, proposition-aware planning, grouped evidence realization,
cross-incident synthesis, explicit pair-scope discipline, and typed advisory
normalization. These constraints improve question satisfaction and discourse
quality without introducing model-created factual prose. Raw historical-memory
payloads have no prompt or renderer path, and missing or present advisory data
never becomes current operational state.
