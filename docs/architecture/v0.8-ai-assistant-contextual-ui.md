# v0.8 Contextual AI Assistant UI

This document describes the read-only SOC Assistant integration on Incident
Detail and Case Detail. It builds on the committed Step 1 backend foundation
and does not add backend routes, write actions, conversation persistence,
streaming, or a global Assistant page.

## Purpose And Supported Pages

The contextual panel helps ADMIN and ANALYST users ask grounded questions about
the object currently open:

- `/incidents/{id}`
- `/cases/{id}`

The panel is placed after the existing AI summary or analysis and before the
main workflow and remediation controls. It receives only the scope, numeric
target ID, display label, and current user role. The backend retrieves all
authoritative context.

VIEWER users do not receive the interactive panel and no Assistant capability
or query request is made for them. Backend RBAC remains authoritative.

## Frontend Architecture

- `frontend/src/lib/assistant.ts` mirrors the Step 1 request and response
  contracts, calls the two Assistant endpoints with `authFetch`, validates
  internal source URLs, and maps failures to stable user-facing states.
- `ContextualAssistantPanel.tsx` owns capability discovery, controls, question
  submission, cancellation, target reset, and the latest in-memory response.
- `AssistantAnswer.tsx` renders plain text, supported inline citations,
  limitations, and allowlisted provider metadata.
- `AssistantSources.tsx` separates authoritative operational sources from
  advisory semantic sources and links only safe internal application paths.
- `assistantPresentation.ts` contains scope-specific question suggestions,
  mode labels, deterministic citation tokenization, and formatting helpers.

The Incident and Case pages do not duplicate Assistant request or state logic.

## Capability Discovery And Roles

For ADMIN and ANALYST, the mounted panel calls:

```text
GET /assistant/capabilities
```

The request is abortable and is made once per mounted contextual target. A
manual retry is available after a safe network or server failure. The query
endpoint is never called during page load.

The capability response controls:

- enabled or disabled state;
- supported scopes;
- supported modes;
- semantic-memory availability;
- the backend decision-boundary statement.

When the feature is disabled, controls remain unavailable and the UI explains
that governed backend enablement is required. A `403` produces a restricted
state. A `401` continues through the existing authentication behavior.

## Request Lifecycle

Questions are submitted only after an explicit user action to:

```text
POST /assistant/query
```

The component:

- trims and validates questions against the Step 1 2000-character limit;
- defaults to `auto` mode;
- defaults semantic memory on when the capability supports it;
- sends exactly one incident- or case-scoped numeric ID;
- blocks duplicate submissions;
- supports Ctrl+Enter and Cmd+Enter while plain Enter adds a new line;
- exposes a Cancel action backed by `AbortController`;
- aborts capability and query requests on unmount;
- does not queue, poll, automatically retry, or automatically submit;
- retains the question after success or failure for analyst refinement.

The component is keyed by scope and target ID. Navigating to a different
incident or case remounts it, aborts active work, and clears the question,
answer, sources, limitations, metadata, and transient errors.

Suggested questions only populate the textarea. They never submit a request.

## Response And Citation Safety

Assistant output is rendered as React text with preserved line breaks. The UI
does not parse arbitrary Markdown or HTML and does not use
`dangerouslySetInnerHTML`.

Only citation tokens matching backend-provided source IDs, such as `[S1]`,
become links to source entries. Unknown citation tokens remain plain text. The
frontend does not create source IDs, infer source metadata, or derive URLs from
citations.

Source links are enabled only for validated internal paths beginning with a
single `/`. Absolute, protocol-relative, malformed, control-character, and
backslash-containing values remain non-clickable.

The response view shows only bounded product metadata:

- response status;
- provider key or type;
- profile;
- model;
- fallback state;
- latency;
- source count.

Raw prompts, context, arbitrary usage data, provider configuration, internal
endpoints, filesystem paths, authentication material, and stack traces are not
rendered.

## Authority And Decision Boundary

SQL-backed operational records are labeled `AUTHORITATIVE`. Qdrant
semantic-memory matches are labeled `ADVISORY`. Semantic similarity does not
prove identity, causality, root cause, severity, closure readiness, suppression,
or remediation approval.

llama.cpp or another governed provider supplies explanation and synthesis only.
The panel cannot change incident or case state. Human review and deterministic
platform controls remain authoritative.

Backend-provided limitations are shown by default beneath the response.

## Error And Empty States

The panel includes explicit loading, disabled, restricted, validation, empty,
success, fallback, unavailable, cancellation, and retryable-error states.
Messages for validation errors, missing incidents or cases, disabled
capability, provider timeout, and unknown failure do not expose raw backend
details.

Fallback responses remain renderable with their normalized sources and
limitations. A failed question is retained and may be retried manually when
the error is retryable.

## Accessibility And Responsive Behavior

The panel uses a visible textarea label, native radio controls, a native
semantic-memory checkbox, descriptive button names, keyboard instructions,
polite live regions for progress and completion, alert semantics for critical
errors, and focus movement to a completed response.

Source authority is stated in text and not conveyed by color alone. Internal
link labels include the source identity. Controls and source items stack at
narrow widths, suggestions wrap, answer text breaks safely, and metadata
truncates with full values available through `title`.

## Persistence And Deferred Features

Question, answer, source, limitation, and metadata state exists only in the
mounted React component. It is not written to local storage, session storage,
IndexedDB, cookies, URL parameters, or a backend conversation store. Refreshing
or leaving the target discards it.

Deferred work:

1. global Assistant page;
2. persistent conversations;
3. streaming;
4. project documentation indexing;
5. Assistant observability and evaluation.
