# v0.8 Contextual AI Assistant UI

## Placement And Access

The read-only Assistant panel is integrated into Incident Detail and Case
Detail. It receives only scope, target ID, display label, and role; the backend
retrieves authoritative context. ADMIN and ANALYST can use it. VIEWER does not
receive the panel and remains denied at the API boundary.

The panel stores its conversation timeline in component memory. Changing target
cancels the active request and clears local state. There is no browser
conversation persistence, streaming, or autonomous execution. The global
Assistant workspace uses the same response presentation for global analytics.

## Interaction

Suggested questions populate the editor but never submit automatically.
Submission is explicit, message length is bounded, and a request can be
cancelled. Capability readiness can be refreshed manually; the frontend does
not poll or prewarm the model.

The only active modes are `auto` and `standard`; both resolve to the gateway's
fixed standard profile. Runtime status reflects gateway `warming`, `ready`,
`failed`, or `stopped`.

## Grounded Rendering

`AssistantAnswer.tsx` renders backend-typed plain-text blocks in response order
and labels only the section kinds supplied by the response. The visible
hierarchy is:

```text
Generated analysis
Evidence and sources
Limitations
Technical details
```

Each block renders backend-owned source links next to its text. Selecting a
source link focuses the corresponding entry in the visible source inventory.
Source authority and provenance remain explicit, full record identifiers remain
auditable, and links are accepted only when they resolve to safe internal paths.
Raw JSON, internal prompt labels, hidden reasoning, and model-generated source
syntax are not rendered.

Technical details are collapsed by default and retain the complete response
metadata contract, including request mode, effective profile/model, validation,
fallback, semantic proof/retrieval, context construction, planning, generation,
tokens, timings, retry/model-switch counts, and authoritative analytics fields.
Runtime capability details separately expose readiness, loaded profile,
embedding backend/cache, and semantic-proof runtime data where available.

## Sibling Generation

Incident and Case initial loads can retrieve authoritative data, stored AI
results, deterministic recommendations, and health. They do not create new
playbook or remediation generations.

Explicit controls submit generation through POST endpoints and show `Queued`,
`Running`, `Completed`, or `Failed`. Synchronous refs and disabled controls
prevent duplicate submission while a task is queued or running. The
Contextual Assistant keeps priority over these sibling tasks in the gateway.

## Safety

Assistant output and playbook/remediation suggestions remain advisory.
Frontend controls cannot change incident or case state, severity, Detection
Control, remediation approval, or execution. Existing backend RBAC, audit, and
human approval boundaries remain authoritative.
