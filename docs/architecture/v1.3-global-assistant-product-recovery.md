# Global Assistant Product Recovery

## v0.8 Release Status

This document describes the committed Global Assistant architecture released
with AI SOC v0.8.0. The last fully validated objective product measurement is
`7.79 / 10`; it is a project engineering metric, not an industry benchmark.

Open-language generalization, complex temporal requests, ambiguity resolution
and multi-turn composition remain imperfect. Some answerable requests can
still fail closed or use deterministic fallback. The subsequently evaluated
structured-semantic-parser experiment did not pass protected generalization
gates and is not part of this architecture or release.

## Purpose

The Global Assistant accepts open English and Italian SOC language while
keeping execution closed. Independent atomic decisions are augmented by
compositional interpretation and bounded whole-plan ranking:

1. local Stanza language identification and Universal Dependencies parsing;
2. a local multilingual MPNet encoder with versioned linear heads for closed
   analytics-plan and source-plan candidates;
3. multilingual E5 and UD evidence for actions, target roles, entities,
   negation, temporal roles and open-set detection;
4. coherent candidate scoring using semantic likelihood, dependency roles,
   authoritative schema compatibility, typed context and temporal structure;
5. authoritative resolution of host and detection-rule candidates from the
   RBAC-scoped SQL data;
6. a closed `SemanticQueryAST` containing operation, source, target,
   aggregation, distinctness, positive and negative filters, dimensions,
   ordering, limit, time windows, comparison windows and typed conversation
   references;
7. validation against the closed analytics registry before SQLAlchemy or
   reference execution;
8. typed analytical proof units, one Qwen generation at most, V3.2 semantic
   proof, and atomic model-response or deterministic-fallback publication.

Natural language never supplies table names, columns, joins, functions,
operators or SQL fragments. The interpreter contains no regular-expression
NLU, sentence-template router, phrase-presence dispatch, acceptance-query
branch or generated SQL path. The local ranker emits only identifiers from the
closed analytics and source-plan registries; it cannot emit SQL, prose, facts,
references or an answer. It is therefore not a second answer-generation path.

## Authority Hierarchy

- SQL records remain `OPERATIONAL_AUTHORITATIVE` and are RBAC-scoped before
  selection, grouping or aggregation.
- Registered deterministic results remain `ANALYTICAL_DERIVATION`.
- Platform-recorded correlations remain operational relationships.
- Deterministically constructed cross-incident relationships remain
  analytical derivations.
- Qdrant remains semantic discovery/support only; candidate IDs are rehydrated
  and authorized through SQL before use.
- MITRE definitions come only from the bounded local reference catalog.
- Model-authored references and prior generated prose are never authority.

## Local Runtime

The semantic layer is non-generative and offline at request time:

- Stanza 1.11 EN/IT `tokenize,pos,lemma,depparse` no-charlm packages;
- `intfloat/multilingual-e5-small` on CPU;
- `sentence-transformers/paraphrase-multilingual-mpnet-base-v2` on CPU with a
  versioned safetensors head;
- dateparser, text2num and python-dateutil after typed temporal composition.

The API starts an asynchronous prewarm for the Stanza language pipelines, E5
concept vectors and joint MPNet ranker. Runtime loaders disable model downloads.
Provision the assets explicitly with `scripts/provision_semantic_nlu_models.py`;
paths may be overridden with `AI_SOC_SEMANTIC_NLU_MODEL_DIR`,
`AI_SOC_SEMANTIC_NLU_EMBEDDING_MODEL`, `AI_SOC_SEMANTIC_NLU_JOINT_MODEL` and,
for controlled validation only, `AI_SOC_SEMANTIC_NLU_JOINT_HEAD`.

The head is reproducible with `scripts/train_global_semantic_plan_ranker.py`.
Its metadata records class order, encoder name, counts and SHA-256 digests. The
training inputs are the pre-existing development split plus independently
authored structure-first realizations from
`scripts/global_semantic_plan_development_set.py`. The frozen 150-query
challenge is not imported, read or transformed by either training module and
is not used for thresholds, examples, routing rules or calibration.

## Closed Analytics Algebra

The registered execution surface supports bounded list, count, count-distinct,
top/frequency, distribution, daily trend, period comparison, host comparison,
recorded relationship lookup, semantic candidate discovery and MITRE reference
lookup. Filters are typed and support equality, set membership and their
negative forms. Temporal windows are half-open UTC intervals resolved in
`Europe/Zurich`, including rolling, calendar, day-part, boundary, time-only and
absolute range expressions.

Typed conversation state stores the preceding plan fingerprint, operation,
entity, filters, dimensions, time/comparison windows and authorized result IDs.
Follow-ups extend that state; generated prose is not read back as evidence.

Temporal interpretation builds typed structures for anchor, direction,
quantity, unit, calendar period, boundary, day part and comparison window from
UD-connected spans. Number words are converted only inside those typed spans.
dateparser/dateutil then materialize half-open UTC intervals in
`Europe/Zurich`; they do not decide the analytical meaning of the query.

## Supported Boundaries

The Global scope covers authoritative incident/case counts and lists, hosts,
detection rules, recorded status/risk, MITRE distributions/reference,
case-SLA state, recorded correlations, semantic similarity candidates and
advisory requests backed by Qdrant knowledge sources. A closed source-plan head
distinguishes operational analytics, operational facts, references, playbooks,
investigation guidance, remediation, relationships, similarity and unsupported
requests. Playbook, investigation and remediation plans bypass SQL analytics
and can retrieve advisory context. Source ownership is resolved before
execution: references can enter the analytics builder only for registered
reference lookup, relationships only for recorded-relationship lookup, and
similarity only for semantic discovery followed by SQL rehydration. A plan
whose execution strategy does not belong to the selected source domain is
rejected before its executor runs. Unsupported, ambiguous or unavailable
evidence remains fail-closed. Qdrant content stays advisory and cannot become
an operational fact. Platform facts execute only where a typed authoritative
provider exists.

Security invariants remain unchanged: one Qwen call maximum, no retry, repair,
critic, rewrite, model switch or cloud inference, and deterministic fail-closed
publication after any schema or semantic-proof failure.
