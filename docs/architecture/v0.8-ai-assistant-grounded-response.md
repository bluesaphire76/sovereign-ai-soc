# v0.8 Grounded Assistant Response

## Data Flow

The Contextual Assistant remains read-only and scoped to the open incident or
case:

```text
authoritative SQL -> typed facts -> optional Qdrant advisory context
                  -> semantic FocusedFactView
                  -> one typed-claim generation through the gateway
                  -> exact grounding and structural focus validation
                  -> deterministic localized rendering
```

SQL retrieval produces a deterministic fact inventory. Missing fields remain
`null`; they are not inferred. Qdrant is advisory, uses a hard budget of at
most two seconds, requires a ready local embedding model, performs no
generative reranking, and fails open.

## Model Contract

The model returns one `assistant_grounded_v2` JSON object. It cannot return
operational prose:

```json
{
  "claims": [
    {
      "claim_type": "RECORDED_FACT",
      "field": "risk_score",
      "value": 35,
      "provenance": "recorded_operational",
      "source_ids": ["S1"]
    }
  ],
  "next_check": null,
  "limitations": [],
  "used_advisory_context": false
}
```

The closed Pydantic schema rejects additional properties. Claim types, fact
fields, provenance, limitations, advisory guidance, relations, and next checks
are enums. The prompt contains the focused facts, accepted advisory text, the
analyst question, and backend-assigned allowed source IDs. One Assistant
request makes at most one generative call.

## Local Validation

`FactFieldPolicy` declares each known field's family, exact value type,
authority, semantic role, provenance, and focus dimension. Grounding compares
each claim directly with the `FocusedFactView` and allowed source registry.
There is no regex, keyword, substring, phrase, or token-based semantic parsing.

Canonical incident severity, risk-normalization severity, and recommended
priority have distinct provenance. Risk bands, derivations, status meaning,
threat, urgency, impact, compromise, and escalation require explicit matching
facts. Correlation-to-compromise and correlation-to-causality are allowed only
as typed non-implication relations. Validation never calls another model.

## Fallback

Gateway failure, queue deadline, generation timeout, invalid JSON, grounding
failure, or focus failure produces one deterministic English or Italian
response from the same focused fact inventory. The same deterministic English
or Italian renderer handles both accepted model claims and fallback claims.
It does not parse the analyst question or claim generative provider attribution.

## Backend Source Attribution

The backend assigns `S1`, `S2`, and later IDs before generation. Authoritative
records are ordered first. Claims may reference only IDs in the prompt source
registry and must match the required authority. Direct, analysis, next-check,
and limitation blocks reference only source IDs from validated claims.

The frontend renders Direct answer, Analysis, Next check, and Limitations as
plain-text blocks with adjacent source chips. A collapsed source inventory and
slim technical details remain available. Model-generated citation syntax and
citation-repair inference are retired.
