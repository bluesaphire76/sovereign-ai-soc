# AI Assistant V3.1 Part A: Conversational Recovery

## Boundary

V3.1 replaces only the failed normal response-writing and contextual UI layers.
The V3 context package, SQL authority, Qdrant candidate boundary, semantic
intent/focus routing, cross-incident graph, relationship registry,
authorization, conversation refs, gateway, metrics, and deterministic fallback
remain in place.

The normal path is:

```text
authenticated contextual query
  -> shared semantic intent/focus embedding
  -> authorized SQL and optional semantic retrieval
  -> closed V3 analytical context package
  -> one schema-constrained conversational generation
  -> deterministic claim/ref/authority/scope validation
  -> model-authored visible prose
```

`GroundedConversationalAnswerV31` contains closed visible segments and closed
typed claims. Every visible segment references claims. Evidence claims
reference only IDs in the model-visible V3 package; absence, non-implication,
and limitation claims use closed codes and cannot carry evidence refs. There is
no free-text authority field.

`GroundedConversationalAnswerV31Validator` resolves refs structurally through
the atom, candidate, knowledge, and relationship registries. It rejects
dangling refs, authority promotions, explicit-comparison drift, unsupported
high-risk implications, missing relationship caveats, and language mismatch.
The validator uses the same bounded evidence view serialized into the model
prompt, so a ref that exists in the wider authorized package but was not
exposed to the model is rejected.
It performs no model call and no JSON repair. Narrow literal checks are only
defensive guards for unsupported compromise, actor/campaign, causality,
maliciousness, escalation, severity/risk band, business impact, lateral
movement, and persistence assertions; they do not route intent or infer facts.

## Failure And Rollback

Malformed, truncated, or rejected V3.1 output is never shown. There is no
retry, critic, repair, rewrite, or second model. The existing validated V3
answer plan and `RichGroundedDiscourseRenderer` produce the emergency fallback.
If that layer fails, the existing minimal deterministic fallback remains.

The single rollout key accepts:

```text
AI_ASSISTANT_RESPONSE_ARCHITECTURE=v3_1  # Part A proof gate
AI_ASSISTANT_RESPONSE_ARCHITECTURE=v3    # Milestone C deterministic renderer
AI_ASSISTANT_RESPONSE_ARCHITECTURE=v2    # legacy rollback only
```

Changing the value and restarting the API is sufficient; no data migration is
required. Do not overwrite a deployment `.env` or remove the V3/V2 paths while
manual product acceptance is pending.

## Semantic Runtime

The configured semantic phase budget starts when semantic retrieval starts.
Its effective deadline is:

```text
min(semantic_phase_started + semantic_budget, global_request_deadline)
```

API startup retains one tracked embedding prewarm worker. Intent, focus,
knowledge retrieval, and the incident semantic index reuse the process cache;
normal requests use `require_ready_embedding` and therefore do not instantiate
SentenceTransformer synchronously when prewarm is incomplete.

The response exposes the closed states `not_requested`, `disabled`, `warming`,
`embedding_unavailable`, `qdrant_timeout`, `retrieval_timeout`,
`retrieval_failed`, and `available`. Authoritative SQL evidence remains usable
on every degraded semantic state.

## Delivery Protocol

The current llama.cpp provider abstraction and AI Execution Gateway return one
complete schema-constrained JSON object with provider streaming disabled. A
segment cannot be parsed and deterministically validated before the complete
object is available, and emitting unvalidated prose would violate grounding.
No `/assistant/query/stream` endpoint is advertised.

The truthful fallback UX immediately appends the submitted user turn and an
assistant pending/status turn. It replaces that pending turn with the complete
validated answer or a turn-scoped error. It never reveals precomputed text one
character at a time.

## Contextual UI

The Incident and Case panels keep a message timeline for the mounted context.
Follow-up submission does not erase prior turns. Normal assistant content is
shown as connected prose without per-paragraph report headings, borders,
provenance badges, or source-button clusters. Sources, provenance, semantic
state, validation, architecture, generation count, retry/model-switch counts,
and latency stages remain available in collapsed details.

The frontend conversation is ephemeral. The backend continues to store only
owner/scope-bound validated refs with TTL; generated prose is never
authoritative state.
