# AI Assistant V3.2 Hybrid Semantic Grounding

## Objective

V3.2 closes the V3.1 gap between a valid source reference and a semantically
supported proposition. The local generative model writes one bounded structured
draft. A separate non-generative proof system decides whether every visible
proposition may be published.

The normal path performs exactly one AI Execution Gateway generation. There is
no critic, repair, retry, citation rewrite, second model generation, cloud
inference, free-form NL-to-SQL, or model-authored provenance.

## Pipeline

```text
authorized V3 analytical context
  -> typed EvidenceProofUnit compilation
  -> one Qwen structured draft
  -> one proposition / one-to-four proof-unit obligation
  -> typed semantic guards
  -> multilingual NLI only when deterministic proof is insufficient
  -> whole-response PASS or deterministic grounded fallback
  -> attribution derived from accepted proof units
```

Each proof unit closes its authority, evidence kind, scope, predicate, canonical
value, required anchors, semantic role, provenance, and source refs. The
response contract permits at most 8 atomic propositions and 4 section kinds.
Every proposition has one to four proof refs, allowing a single sentence to
combine values only when every contributing typed unit is selected. Every
proposition is rendered exactly once, and the model cannot submit source or
provenance fields.

## Authority

The proof compiler preserves the V3 authority hierarchy:

| Evidence | Authority | Maximum role |
| --- | --- | --- |
| operational fact | `OPERATIONAL_AUTHORITATIVE` | recorded value |
| recorded correlation | `OPERATIONAL_AUTHORITATIVE` | recorded relationship |
| analytical relationship | `ANALYTICAL_DERIVATION` | analytical comparison |
| semantic similarity | `SEMANTIC_CANDIDATE` | candidate discovery |
| reference knowledge | `REFERENCE_KNOWLEDGE` | technical explanation |
| advisory knowledge | `ADVISORY_KNOWLEDGE` | investigation guidance |
| typed synthesis | `ANALYTICAL_DERIVATION` | grounded synthesis |
| analytical boundary | `ANALYTICAL_DERIVATION` | uncertainty boundary |

SQL-derived operational data remains authoritative. Qdrant can discover a
candidate but cannot establish operational state. Reference knowledge cannot
establish current state, and advisory knowledge cannot establish what happened.

## Hybrid Proof

Typed guards reject incompatible concepts, changed entity or numeric values,
missing required anchors, polarity conflicts, authority promotion, causal or
compound overreach, and reference/advisory state promotion. Closed predicates
with complete controlled-value coverage receive deterministic proof. Open
explanatory or advisory propositions also require entailment from the pinned
multilingual NLI provider.

Deterministic analytical relationships carry the authoritative shared value
that produced them, while their source atoms remain operational authoritative.
Typed non-implication boundaries state what risk, MITRE associations,
correlations, semantic candidates, and analytical relationships do not prove.
An operational fact may share a proposition with a boundary only when the
boundary structurally references that same operational source. A context
limitation may state that no relevant advisory was retrieved, but it has no
external source ref and cannot establish operational state.

Intent contracts require cross-incident answers to include a relationship and
its uncertainty boundary, comparisons to use pair-scoped relationships, and
next-action answers to use retrieved advisory evidence or the typed advisory
context limitation. Explicit comparisons and their follow-ups retain only the
selected incident set; unrelated discovery candidates do not enter that model
surface.

The selected provider is
`MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli`, revision
`0a71e92a985b6e1ad1828cf67ce9c459639c1dca`, MIT license. The pinned
`model.safetensors` is 427,997,022 bytes with SHA-256
`91b323ccf247ec1e3b5925d566230bae7c52de8147e6062b42e250089a3fc80b`.
Runtime loading is GPU-only, FP16 by default, local-files-only, path pinned, and
guarded by that exact weight size and digest. No download or CPU fallback is
possible at runtime. The API prewarms it only when the Assistant and V3.2 are
enabled. A single serialized executor applies a three-second bounded proof
timeout after a real warm-up inference during API prewarm.

Any unsupported proposition, invalid structure, unknown proof ref, provider
failure, timeout, or rendering failure discards the complete draft. The
existing typed V3 deterministic plan and discourse renderer produce the useful
fallback; the generative model is never invoked again.

## Operations

`AI_ASSISTANT_RESPONSE_ARCHITECTURE=v3_2` selects V3.2. The repository retains
`v3_1`, `v3`, and `v2` as explicit rollback paths. V3.2 exposes bounded metadata
and Prometheus metrics for proof status, duration, pair count, guard rejects,
deterministic proofs, NLI proofs, selected model/revision, fallbacks, and the
existing generation/retry/model-switch counters. No record or user identifier
is used as a metric label.
