# AI Assistant V3: Milestone C Production Quality

## Production Boundary

Milestone C productionizes the grounded analytical pipeline delivered by
Milestones A, B, and B.1. It does not add an execution capability or a second
generation path. The request boundary remains:

```text
authenticated Assistant request
  -> semantic embedding intent/focus routing
  -> authorized authoritative retrieval
  -> typed evidence and relationship registries
  -> one schema-constrained provider generation
  -> deterministic validation and rendering
```

SQL/API records remain operational authority. Qdrant returns candidate IDs
only; every candidate is authorized, rehydrated from SQL, and fingerprint
checked before it can enter the context package. Recorded correlation,
analytical derivation, reference knowledge, advisory knowledge, and semantic
candidate authority remain separate.

## Semantic Routing

Intent routing is embedding-driven and non-generative. Each closed intent has
a bounded bilingual set of declarative prototypes. Prototype embeddings are
cached and a request is compared by cosine similarity. There is no regex,
keyword, substring, exact-question, or record-specific route. An unavailable
encoder or a genuinely low-confidence request degrades to the neutral summary
intent.

Focus routing retains the same embedding-only boundary. Neither router invokes
the provider model. The one provider generation is reserved for the grounded
answer plan.

## Cross-Incident Authorization

`PlatformIncidentAccessPolicy` applies the current platform role boundary to
every incident ID before candidate facts are exposed. The same policy filters:

- recent, exact, case-linked, explicit-comparison, and semantic candidates;
- linked case membership before atom normalization;
- conversation incident references during load;
- the graph, relationship registry, model-facing package, visible sources,
  and persisted validated conversation state.

The current product has global `ADMIN` and `ANALYST` incident visibility rather
than row-level ACLs. The typed policy is injectable so a future tenant or
row-level predicate can be enforced at the same pre-exposure boundary.

## Conversation Isolation

The UI creates a new opaque conversation ID for each mounted Incident or Case
context. Navigation changes the component key and discards the previous local
thread. The backend keys state by authenticated owner and conversation ID,
validates active scope IDs, drops deleted or unauthorized refs, enforces TTL
and per-owner/global limits, and persists no Assistant prose as evidence.

## Response and Provenance UX

The Incident and Case contextual panels preserve non-empty V3 sections such as
direct answer, findings, evidence, related incidents, comparison, pattern,
conclusion, limitations, and recommended checks. Sources are grouped with
readable provenance labels:

- Operational source;
- Reference knowledge;
- Advisory / playbook;
- Analytical relationship;
- Semantic candidate.

Incident and case sources link to existing detail routes. Semantic candidates
carry a retrieval-only caveat, while recommended checks are visibly guidance.
Detailed intent, scope, grounding, semantic-index, model, and stage metadata
remain behind the technical-details affordance.

## Typed Quality Contracts

A focused fact lookup cannot substitute an unrelated identity or handling fact
when the requested field is absent. The requested typed field remains in the
context policy, absence is checked against the primary record scope, and the
schema permits only a typed absence result when that absence is material. A
priority recorded on a case-linked incident does not become case priority.

Comparison uses mutually available status, host, detection, risk, MITRE, and
recorded-correlation atoms. Record identity and timestamp establish scope but
do not manufacture an analytically useful difference. When every comparable
pair is equal, the validated plan must include
`NO_RECORDED_DIFFERENCE_IN_COMPARED_FIELDS`; the renderer states that no
different values are recorded in the available comparable fields.

For `EXPLAIN`, when detection, host, and risk atoms are available for the
primary incident, all three are required in the direct grounded proposition.
This completeness contract is typed and intent-level; it does not inspect
question strings.

## Bounds and Failure Handling

All model-facing collections remain closed and bounded: prompt characters,
atoms, candidates, graph records and edges, knowledge atoms, plan sections and
units, refs, sources, and conversation state. V3 continues to fail closed on a
gateway error, deadline, malformed structured output, invalid plan, missing
dependency, or renderer failure. It does not repair JSON or retry generation.

The timeout hierarchy is:

```text
Assistant deadline 45s > gateway deadline 35s > provider timeout 30s
semantic and Qdrant retrieval budget 2s
```

Local benchmark cooldown may occur between completed requests to prevent
laptop GPU thermal throttling. It is never included in per-request latency and
does not change runtime deadlines.

## Observability and Audit

Response metadata and Prometheus metrics expose bounded stage durations and
counts for intent, focus, conversation, scope, policy, operational retrieval,
normalization, semantic retrieval, rehydration, graph, reference/advisory
retrieval, schema, generation, validation, rendering, and total latency.
Labels are fixed low-cardinality dimensions; incident, case, user,
conversation, and host IDs are forbidden.

Completion audit records contain request identity, scope, bounded source IDs
and provenance classes, grounding/generation status, and model/profile. They do
not persist prompts, raw records, answers, or hidden reasoning.

## Rollout and Rollback

V3 is the repository and production default. The single rollout control is:

```text
AI_ASSISTANT_RESPONSE_ARCHITECTURE=v3
```

After restart, verify a contextual response reports `assistant_version=v3`, a
passed grounding and plan-validation status, one provider generation, and no
fallback. Roll back without data migration by setting:

```text
AI_ASSISTANT_RESPONSE_ARCHITECTURE=v2
```

and restarting the API through the normal service workflow. V2 does not share
V3 conversation state as authority, and the incident semantic index remains
retrieval support only.

## Non-Implications

Production rendering and validation preserve these boundaries:

- risk and recommended priority do not establish canonical severity;
- missing or present escalation reason does not establish escalation state;
- recorded correlation does not establish compromise;
- analytical relationship does not establish causality, actor, or campaign;
- same host, technique, case, or time window does not establish one attack;
- semantic similarity is not platform-recorded correlation;
- advisory and reference knowledge do not establish current record state.
