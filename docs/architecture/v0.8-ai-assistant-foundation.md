# v0.8 AI Assistant Foundation

## Current Status

The Step 1 retrieval, RBAC, audit, source-registry, and read-only safety
foundations remain active. The distributed generation runtime developed during
the uncommitted Step 2 sequence has been replaced by:

- [AI Execution Gateway](v0.8-ai-execution-gateway.md);
- [Grounded Assistant Response](v0.8-ai-assistant-grounded-response.md);
- [Contextual AI Assistant UI](v0.8-ai-assistant-contextual-ui.md).

Assistant-owned model prewarm, automatic profile routing, model-generated
source tokens, citation-repair generation, and reasoning retries are not part
of the current runtime.

## HTTP Boundary

Authenticated ADMIN and ANALYST users can call:

```text
GET  /assistant/capabilities
POST /assistant/query
```

VIEWER is denied by backend RBAC. Requests are closed Pydantic contracts for
global, incident, or case scope. Incident and case IDs must match the selected
scope. The Assistant has no write actions, autonomous tools, streaming,
persistent conversation history, or project-document indexing.

## Retrieval

`services/assistant/retrieval.py` reads authoritative incident or case records
through SQLAlchemy and constructs a typed fact inventory. Qdrant contributes
optional advisory records only when local embeddings are already ready and
the deterministic relevance gate accepts them. The semantic budget is at most
two seconds and failure does not block authoritative answers.

`services/assistant/context_builder.py` encodes facts, advisory context, and the
analyst question as bounded JSON. It does not expose backend source IDs to the
model.

## Execution And Validation

`services/assistant/orchestrator.py` submits one structured request to the
single-owner inference gateway. `services/assistant/grounding.py` validates
hard-fact novelty, contradictions, safety, language, and focus locally.
Failure produces one deterministic fallback without a second generation.

`services/assistant/sources.py` orders authoritative sources before advisory
sources and assigns IDs only after validation. Response blocks cannot refer to
an unknown source.

## Audit Safety

Audit records include scope, target ID, a SHA-256 message digest, message
length, generation kind, safe latency and validation states, fallback reason,
language, and source counts. They never include the question, prompt, answer,
source excerpts, embeddings, hidden reasoning, provider secrets, or internal
exception strings.

## Configuration

The feature remains controlled by `AI_SOC_ASSISTANT_ENABLED`. Message, context,
source, and semantic limits remain bounded. All generative execution settings
come from the gateway configuration documented in `.env.example`; active
callers cannot select a different provider or profile.
