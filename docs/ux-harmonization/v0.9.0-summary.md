## Design-System Decisions

- Evolve the existing Enterprise family, semantic helpers and native controls.
  No duplicate component families or theoretical unused Drawer/Dropdown layers.
- Dark operational surfaces, bounded workspaces, dense tables and quiet headers.
  Executive remains lower density; Dashboard medium/high; investigations,
  detection, operations and governance high density; Login compact.
- Shared shell, header/breadcrumbs/actions, metrics, sections/panels, badges,
  selects/search, states and native dialogs. Page archetypes retain distinct jobs;
  consistency does not mean identical layouts or removed functionality.
- Severity: **CRITICAL red; HIGH orange/red-orange; MEDIUM amber; LOW blue/slate-blue;
  unknown/null neutral/slate**. Green is primarily healthy, successful, resolved
  or completed. Text remains alongside color. Backend severity values unchanged.
- Health/status: success/healthy green, degraded/warning amber, failure/error red,
  information blue and unknown/unavailable neutral. No invented domain states.
- Final accessibility pass: targeted readable metadata foreground token, visible
  focus, skip link/main landmark, mobile Escape/focus return, long-title wrapping,
  named keyboard scroll regions, explicit labels, reduced motion and short native
  dialogs with focus restoration on unmount. No global visual redesign.

## AI And Governance

Generated analysis is labeled; deterministic fallback is distinct. Grounding and
semantic proof have explicit textual states. Authoritative operational records,
analytical relationships, semantic candidates, reference knowledge and advisory
playbooks remain differentiated; semantic similarity does not imply authority.
Sources are keyboard reachable, citations focus their source, limitations stay
visible, and technical metadata is expandable. Cancellation does not insert a
late response. No AI write capability or grounding logic changed.

Backend remains authoritative. Incident/Case actions, closure evidence and
approval, Detection Control preview/validation/reason/confirmation, service
restart gating and Users safeguards remain. Tests use fixtures and isolated
databases; no destructive production action was used for UX validation.

**Pre-existing HIGH governance risk:** the sole ADMIN can demote itself and leave
zero active administrators; self-delete/disable guards do not prevent this.
Immediate database-role recheck correctly blocks stale ADMIN privileges, including
self-restoration. Recommend blocking the tag until a separately approved safeguard
or explicit documented risk acceptance with tested recovery. UX-12 does not add
unapproved backend governance logic.
